# Minutes of Meeting

**Date:** 12 October 2026
**Participants:** Mahaveer, Anurag, Balu, and Debee
**Objective:** Finalize the approach for automatically generating Momentec garment proofs and integrating them with the existing AI Creator and Comms workflow.

## Discussion

### 1. Customer input and experience

- Gender and garment size fields were added to improve artwork placement and garment-shape accuracy.
- AI may be able to infer gender from the uploaded garment, but retaining the gender field provides a reliable fallback.
- The UI demonstrated during the meeting is only a proof of concept and will not be used in production.
- The existing AI Creator form will remain the customer-facing form.
- After submission, customers should immediately see a thank-you confirmation instead of waiting for the PDF to be generated.
- All proof-generation activities must run asynchronously in the backend.

### 2. Style detection and garment accuracy

- The generated garment must match an actual Momentec style rather than use a generic AI-generated shirt shape.
- Small differences in garment cut, sleeve length, body length, and sport-specific construction can affect the printed result.
- The existing style-detection capability will be enabled.
- The vector database currently contains:
  - Style number
  - Style description
  - Long description
  - Sport
  - Gender
  - Supported text locations
  - Mascot locations
- Once the style is identified, the system will call the Momentec product API to retrieve the correct blank front, back, and other available reference images.
- These blank images will be supplied to the AI as shape references when generating the proof.

### 3. Artwork and decoration information

- AI currently identifies artwork locations, logos, text, numbers, and colors from the generated garment views.
- Decoration SVG files are not required for the immediate proof-generation workflow.
- The proof initially requires front and back garment images and the associated decoration information.
- SVG/vector assets may continue to be generated for future artist automation, but they are not part of the current customer proof requirement.

### 4. Color handling

Two color scenarios were identified:

- When the customer explicitly requests exact colors or supplies PMS values, the proof must use those requested colors.
- When exact colors are not requested, uploaded artwork colors must be mapped to the closest approved Momentec colors.

The approved CMYK and PMS mappings are private business information and must:

- Remain on the backend.
- Never be returned through a public API.
- Never be exposed in the customer-facing application.
- Be accessed only by the proof-generation service.

### 5. PDF proof generation

The generated PDF must follow the existing Momentec proof format. It must contain:

- Correct front and back garment views.
- Actual Momentec style information.
- Customer and request information.
- Decoration details.
- Artwork colors and PMS information where applicable.
- Comments or special color instructions.

The PDF and related assets must use the existing proof-storage location and naming convention. Once uploaded, a final API call will associate the generated proof with the appropriate Comms mock-up request.

### 6. Integration architecture

The agreed backend process is:

1. AI Creator form submission
2. Asynchronous job
3. Style detection
4. Retrieve blank style images
5. Generate garment views
6. Extract and map colors
7. Generate PDF
8. Upload to S3 / proof storage
9. Update Comms

- The existing AI Creator form already creates the Comms mock-up request.
- The new proof-generation job will be triggered when that form is submitted.
- The service should be implemented as a reusable AWS serverless component.
- AWS Lambda was proposed so the service remains idle when unused and can be reused by other applications.
- The current Magnific integration, style knowledge, color logic, PDF generation, and storage logic should be packaged into this service.
- The longer-term objective is to convert this into a reusable job-management capability.

## Decisions

- Use the existing AI Creator form. Do not use the POC form.
- Generate proofs asynchronously after form submission.
- Display an immediate thank-you message to the customer.
- Detect the actual Momentec style before generating the proof.
- Use Momentec blank product images as shape references.
- Produce the proof using the existing Momentec PDF format.
- Use S3 / existing proof storage and the established naming convention.
- Update the Comms request after proof generation.
- Keep private PMS and CMYK information backend-only.
- Package the solution as an AWS serverless service.
- Regroup Wednesday or Thursday to validate the integrations.

## Dependencies

- Vector-database access.
- Momentec blank product-image API documentation.
- Existing Comms API details.
- S3 / proof-storage path and naming convention.
- Secure access to the approved Momentec color library.
- Existing PDF proof template and required field mappings.

## Risks and open questions

- Accuracy of automatic style detection from uploaded artwork.
- Consistency between generated proof images and the production garment’s actual cut.
- Handling requests where no confident style match is found.
- Secure use of non-public PMS and CMYK mappings.
- AI consistency when reproducing complex designs.
- Retry and failure handling for long-running AI generation.
- Whether Lambda alone is sufficient for the complete processing duration, or whether it requires a queue or workflow around it.
- Artist-review requirements during the initial rollout.
