CDL Express, point to point

Walk this top to bottom. Each box is one piece. Input, call, prompt, model output, and what the next box receives. Region is ap-southeast-2. No secrets are in this page.

1Customer drops a photo

Input
One jpg, png, or webp. Up to 8 photos. Only the first photo is used to guess category and gender, and only the first photo is described for catalog search.
What the browser does
Background removal runs in the browser at 512 px, only to make a mask. That mask is applied to the original and flattened on white, long edge capped at 1536 px. The server flattens any leftover transparency again before any model sees the file.
Output
A flattened photo, still on the page. Category and gender are still empty until step 2 returns.

2Guess category and gender

Endpoint
POST /api/upload-ai-design/suggest
Input
Form field reference: the first photo.
Prompt
SUGGEST_PROMPT. Pick a category from the garment cut, not from a team logo. Youth only if it is clearly a kids cut. Women for a ladies cut. Otherwise Men. Allowed values are the form’s category list and Men / Women / Youth.
Model output
{ "category": "BASEBALL", "gender": "Men" }
Output
Those two dropdowns are filled. If the customer already chose one, that choice is kept. Size, name, and email stay locked.
Failure
400 bad file, 422 or 502 the model could not read it, 503 no API key. The page stays usable. The customer picks the fields by hand.

3Make the four views

Endpoint
POST /api/upload-ai-design/generate. Max 300 seconds.
Input
Form fields reference (photo), gender, category. Both gender and category are required. An edit also sends instruction, template (the blank catalog 2x2), and catalog (the matched style JSON).
Output
JSON: base64 images.front/back/left/right, base64 sheet, style, query, matches, plan, limits (the customer note), template, catalog.
Stop
400 if gender or category is missing, or an edit has no template. 422 if the garment cannot be made or the match is not confident. 502 if Magnific fails. 503 if a required key is missing.

4OpenAI describes the photo

Call
Chat Completions. Schema name describe_garment. Temperature is not sent. Reasoning effort low. One retry, then fail closed. No six-word fallback search.
Prompt
DESCRIBE_PROMPT. Asks for catalog product names (Crew Neck Baseball Jersey, V-Neck Hockey Jersey, and so on), sleeve cut, visible logo places, visible text places. A one-piece singlet, dress, unitard, or similar cut must come back supported: false with a reason.
Model output, pass
{
  "supported": true,
  "queries": ["V-Neck Hockey Jersey", "Long Sleeve Hockey Jersey", "Hockey Jersey"],
  "garment_piece": "top",
  "sleeves": "long",
  "segment": "adult",
  "logo_locations": ["Front Center Full"],
  "text_locations": ["Left Short Sleeve"],
  "has_buttons": false,
  "confidence": 0.8
}
Model output, reject
{
  "supported": false,
  "unsupported_reason": "This is a one-piece wrestling singlet."
}
Next
Pass goes to catalog search. Reject returns 422 with the model’s reason. The page stops. No Magnific call.

Stop — cannot manufacture the garment

When
supported is false, or the piece is one-piece or other.
What the customer sees
The model’s reason. We do not append a hardcoded product list.
What we can make
Separate tops, bottoms, and catalog accessories. That rule lives in DESCRIBE_PROMPT, not in a fixed sentence on the page.

5Catalog search

Endpoint
POST {catalog}/search. The host is the catalog Lambda function URL. Header X-API-Key. Body is JSON, not query params.
Input
Each of up to three queries. top_k 12. Collection products only. group_products_by_style true. Filters: segment from the form gender (Men → adult, Women → ladies, Youth → youth), sport from the category uppercased.
Example body
POST /search
{
  "query": "V-Neck Hockey Jersey",
  "top_k": 12,
  "collections": ["products"],
  "group_products_by_style": true,
  "product_filters": { "segment": "adult", "sport": "HOCKEY" }
}
Output
Styles with style, name, brand, sport, segment, score, logo_locations, text_locations, color_zones. Broken preview prefixes (UP, UFO, UPO, UPB, URS) are dropped. Partner prefixes are down-ranked. The list is cut to distinct cuts, then the top ones that actually return images.
Fallback
If the sport filter returns too few rows, search again without sport. Then without segment. Categories that are not sports (TEES, TOPS) often miss and take this path.

6Blank 2x2 of each candidate

Call
Four GETs per style. The style and view are appended after preview-.
Example
preview-228350_front
preview-228350_back
preview-228350_left
preview-228350_right
Output
One 960×1280 PNG per style. Cells are front, back, left, right, with a white cross. Up to three of these sheets go to the next step. If none of the preview URLs return, the page stops with 422.

7OpenAI picks the style and writes the plan

Call
Chat Completions. Schema name judge_garment. winner_style is an enum of the candidate style codes plus none. One retry. Confidence below 0.6, none, or a style that is not in the candidate list stops the job. Magnific is not called.
Input
The customer photo, then each candidate 2x2 labeled with that style’s name, brand, logo locations, text locations, and color zones.
Prompt
JUDGE_AND_PLAN_PROMPT. Pick the closest cut that can also print the visible logos and text. If the closest cut cannot print them, pick the next candidate that can. Map colors, logos, and text only onto that style’s allowed zones and locations. A logo with lettering inside it is one logo. Do not split the words into text and the picture into a separate graphic. Customer-facing not_possible and can_do are plain language, no style numbers, no codes like m2.
Model output
{
  "supported": true,
  "winner_style": "228350",
  "confidence": 0.74,
  "color_zone_mapping": ["Body Color: scarlet #A31F2D"],
  "logo_mapping": ["Front Center Full (m2): Hays Sluggers crest"],
  "text_mapping": ["Left Short Sleeve (t24): HYB"],
  "not_possible": [
    { "mark": "small label at the front hem", "reason": "this style has no logo spot there" }
  ],
  "can_do": ["Hays Sluggers logo on the front", "number 10", "NAME on the back"],
  "view_plan": { "front": "...", "back": "...", "left": "...", "right": "..." }
}
Code after the model
filterPlanToAllowedCatalog drops any plan line that does not name an allowed code or place. snapPlanColors sends each hex to POST /colors/nearest for that brand (Augusta, High Five, PG, and New Era use the Holloway chips). Tonal and camo chips are skipped. If that call fails, the same nearest-chip search runs on the 173 colors copied into the app. There is no distance cutoff. The closest solid chip wins.
If the winner still cannot print a real mark
A hem tag does not count. If a real logo or text was left off, and another of the three candidates covers more of the detected places, that candidate is judged again by itself and becomes the garment. The four views are then made from that style.
Customer note
limits is two lines when the model returned them. First what was included. Then what was left off and why. Style numbers and location codes are stripped before display. Example: “We made this with the Hays Sluggers logo on the front. We couldn't add the small label at the front hem. This style has no place for a logo there.”

Stop — not confident

When
winner_style is none, is not one of the candidates, or confidence is under 0.6. Also when the JSON is still bad after one retry.
Output
422. Message is the model’s reason, or “An artist needs to review this design before we can make it.” No image is painted.

8Magnific paints the four views

Call
Magnific gpt-image-2-edit. Image 1 is the winning style’s blank 2x2. Image 2 is the customer photo. Prompt is buildCatalogProjectionPrompt. Poll up to 300 seconds.
What the prompt demands
Keep Image 1’s cut, collar, sleeves, buttons, hem, and 2x2 layout. Paint the snapped Momentec hex colors. Paint only the logos and text listed in the plan. If a mark is not on an allowed place, do not draw it and do not move it. A lettering-inside-a-crest logo is one mark.
Output
One 2x2 PNG. The site splits it on the white cross into front, back, left, and right and shows those four pictures, plus the customer note from step 7.
Edit
“Apply this edit” sends the same blank template as Image 1 and adds the customer’s note as one line. It does not invent a new garment. If the template is missing, the route returns 400.

9Customer submits

Endpoint
POST /api/upload-ai-design/submit
Input
The finished sheet PNG, gender, size, category, name, email, message, and the catalog JSON from step 3 (style, locations, zones, plan).
S3 keys
Folder name is job-2026-10-16T21-04-00Z_{uuid} so the console list sorts by time. Files: {jobId}/sheet.png, {jobId}/job.json. Older jobs are a bare uuid and still open.
Then
Lambda invoke, InvocationType: Event, payload { bucket, jobId }. The image is not in the event. The HTTP response is 202 with { "jobId": "..." }. The customer can close the page.

10Proof Lambda

Function
momentec-cdl-proof. Node, 2048 MB, 15 minutes. Handler index.handler. It does not import the Next.js app.
Input
{jobId}/sheet.png and {jobId}/job.json (gender, size, customer name, message, catalog style, locations, zones, plan).
OpenAI
Schema name decoration_list. Prompt DECORATION_LIST_PROMPT. It reads the sheet and returns fill colors, team marks, and roster marks, each with a location code, hex, and a cell. One retry. A bad response fails the job. Marks that are not on the style’s logo or text locations are dropped. Fill colors that are not on the style’s color zones are dropped. Heights snap to that location’s allowed inch sizes.
Colors
Each hex is snapped again with POST /colors/nearest, then the local 173-color list if that call is not configured. The PDF prints the Momentec name.
Pictures
Front and back on the PDF are crops of the approved sheet. They are not redrawn. Magnific isolates each allowed mark on white. Those mark images can still misspell words. That is a known limit.
PDF
{jobId}/proof.pdf and {jobId}/status.json (running, done, or failed). Page 1 uses the real style number, garment name, size, customer name, and customer message. REF#, ecom order number, and artist are still the sample values and are drawn on red.
Example status
{ "state": "done", "pdf": "job-2026-10-16T21-04-00Z_.../proof.pdf" }

11What is deliberately not in this POC

Not built
Comms callback. PMS or CMYK on the PDF. Replacing the sample REF#, ecom order number, and artist. Step Functions. A queue. Auth on the public generate routes. The customer does not download the PDF from the site.
3D button
POST /api/upload-ai-design/model is a separate Magnific path. It is not part of matching or the proof.
